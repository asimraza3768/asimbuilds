What I Would Improve in My Data Pipeline Next

September 15, 2026 | 3 min read

Building the Job Market Intelligence Platform taught me a lot about data quality and medallion architecture. But engineering is an iterative process, and there are several areas I plan to improve as the project scales.

1. Automated Retries

Currently, the pipeline uses fail-fast handling for API errors, raising an exception immediately. While safe, a better future approach would be wrapping the API calls in a retry block (e.g., using Python's `Tenacity` library) with exponential backoff before ultimately failing.

2. Workflow Scheduling

The Databricks workflow currently runs in under 3 minutes, but it is triggered manually. My next step is to configure a CRON schedule within Databricks to execute the pipeline nightly without human intervention.

3. Better Observability

Right now, I rely on Databricks task logs to monitor runs. In the future, I want to integrate Slack or Email alerting so I am notified proactively if the Bronze landing zone receives 0 rows or if data quality checks fail abnormally high in the Silver layer.
