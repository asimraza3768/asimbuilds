Why I Used Amazon S3 for Raw Data Landing

September 28, 2026 | 3 min read

When building my pipeline, it was tempting to extract data from the REST API, transform it in memory using pandas or PySpark, and write it directly to the Silver database. However, I intentionally chose to land the raw JSON in Amazon S3 first.

Decoupling Extraction from Transformation

By dumping the raw JSON into S3, I created an architectural safety net. If there is a bug in my PySpark transformation logic (e.g., failing to parse a nested array correctly), the Databricks job will fail.

Without S3, I would have to re-ping the API to get the data again. This wastes API rate limits and time. With S3, the raw data is safely stored on disk. I can fix my PySpark code and simply re-run the Bronze-to-Silver notebook using the existing data sitting in the S3 bucket.
